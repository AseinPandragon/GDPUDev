■ 四年成长路线：每年都有明确的收获
4 YEARS
唐老狮 C#/Unity 打底 · 大二交付完整 · 大三深入技术 · 大四收割
大一 · 从零到"能跑起来" YEAR 1 · FOUNDATION
C# 地基 + 第一个能玩的小游戏
直接跳过语言去拖引擎组件，是数媒技学生最常见的翻坑方式。这一年就干两件事：
  • C# 四部曲（唐老狮，B站免费）：入门 → 核心，至少啃完这两部，语法和面向对象过关；
  • 第一个小游戏：控制台版贪吃蛇 → Unity 版打飞机 / 平台跳跃，跟唐老狮 Unity 系列的案例做。
环境这一年也要定下来：Unity Hub + Visual Studio + Git（注册 GitHub，第一次 push 就在大一）。
唐老狮 · B站个人空间 C#入门 → C#核心 免费 · 有课后作业
// 年末自检 ↓
✅ 大一年末自检（全过才算过关） ① 能不抄教程独立写出一个 300 行以上、逻辑自洽的小游戏；② 能说清类/继承/接口/事件是什么、什么时候用；③ GitHub 上有第一次提交记录；④ Unity 里能独立完成"建场景→挂脚本→出包"的闭环。
大二 · 从"会写"到"会组织" YEAR 2 · ARCHITECTURE SEED
第一个"完整项目" + 三个系统级封装
  • 补完 C# 四部曲后两部（进阶 + 数据结构与算法），同步开始 LeetCode 简单~中等（每周 3~5 题的节奏即可）；
  • Unity 全模块过一遍：UGUI、物理、动画状态机、音频、存档（PlayerPrefs/JSON 序列化）、场景切换；
  • 第一个完整项目（本年最重要产出）：有主菜单、有教学、有存档、有结算、能重开、打过 exe 或 APK 包能发给别人装——"完整"两个字值钱过一切炫技；
  • 三个系统级封装（架构的种子）：对象池（回收子弹/特效）、全局事件系统（解耦模块）、有限状态机（角色/敌人 AI）。每个都自己封装一遍，再看别人的实现对比。
LeetCode 力扣 Unity 官方文档 对象池 / 事件系统 / 状态机 完整项目 = 本年核心 KPI
✅ 大二年末自检 ① 完整项目能让一个陌生人双击玩通全程不崩、不看说明也会玩；② 三个封装能白板讲清"为什么这么设计、不用会怎样"；③ LeetCode 累计 80 题以上；④ 项目用 Git 管理且提交历史干净（不是一次性传压缩包）；⑤ 看得懂别人项目里 80% 的代码结构。
大三 · 技术深入（简历价值全在这一年） YEAR 3 · GOING DEEP
热更 · 性能 · 架构 · 联机 —— 四座大山
大二的项目证明你"能做"，大三要证明你"做得深"。四条深入线，每条都冲着面试官的问题去：
  • 热更与资源管线：HybridCLR（C# 热更）+ YooAsset（资源打包分发），给自己的完整项目接上热更；研究分包策略——我们真实项目里把"改一行业务代码全量重下 6.55MB"优化到"只重下 0.6MB"，这种案例就是面试的杀手锏；
  • 性能优化：学会 Profiler（CPU/内存/渲染三视图），实战减 DrawCall（合批/图集）、减 GC Alloc（避免每帧 new、字符串处理）、LOD 与遮挡剔除；优化前后必须有数字：帧率从多少到多少、内存峰值降了多少；
  • UI 框架与架构升级：手写一套 UI 框架（层级管理/栈式界面/异步加载），把大二的事件系统升级成模块化架构，理解 MVC/MVVM 在游戏里怎么落；
  • 网络联机：做一个最简联机 Demo（帧同步或状态同步二选一），TCP/UDP、消息协议、断线重连各踩一遍坑。
这一年同时要做两件"场外事"：带项目打 1~2 个比赛冲奖（见比赛页）+ 大三暑期实习必须拿下（秋招 offer 的一半来自转正或实习经历背书）。
HybridCLR · C# 热更新 YooAsset · 资源管线 Profiler / DrawCall / GC UI框架 / MVC 帧同步 / 状态同步 比赛冲奖 →
✅ 大三年末自检（这是校招的分水岭） ① 项目接着热更：改一行业务代码能通过热更生效，说得清补丁包多大、为什么；② 有至少一条带数字的优化记录（帧率/内存/包体前后对比）；③ UI 框架能白板画架构图；④ 联机 Demo 两个人能实际对战；⑤ 拿到一个暑期实习 offer 或一个省级以上比赛奖。
大四 · 收割（秋招不等人） YEAR 4 · HARVEST
作品集终稿 + 面试攻坚
  • 7~8 月提前批就开，开学前作品集必须是终稿：每个项目配 README（架构图 + 技术亮点）、演示视频（60~90 秒）、可下载的包；
  • 面试项目深挖：用 STAR 讲项目，每个技术决策都要能答"为什么不用别的方案"——热更为什么选 HybridCLR 不用 xLua、对象池为什么这么回收，答不上就是减分；
  • 八股与算法收尾：C# 高频（值类型引用类型/GC/装箱/协程本质）、Unity 高频（生命周期/渲染管线/物理时序）、LeetCode 中等题保持手感；
  • offer 决策：平台 > 薪资 > 项目类型（能学到东西的团队 > 钱多但边缘的业务线），第一份工作选成长速度。
薪资与招聘情报页 → 牛客网（面经/爆料） 提前批 7~8 月就开
✅ 大四上学期自检 ① 简历上每一条技术点都有数字或案例支撑，且能被深挖三层不露怯；② 三个项目的演示视频和 GitHub 仓库齐全；③ 牛客上刷过目标公司近两年的面经；④ 内推码到手（找在职学长，比官网直投存活率高）。
💡 一句话总结客户端方向 大一语言地基、大二完整交付、大三四座大山（热更/性能/架构/联机）、大四把深度换成 offer。面试官问"你这个项目的内存峰值多少、包体多大、为什么这么设计"——每一问的答案都在对应年级的产出里。
■ 毕业前该摸过的五个深入课题
5 PROJECTS
项目多了之后要挑 1~2 个"钻到底" · 这才是和同龄人拉开差距的地方
DEEP_01 · 热更全链路 HYBRIDCLR + YOOASSET
给完整项目接上热更，并回答三个问题
补丁包为什么是这个体积？版本回滚怎么做？AOT 缺失怎么补？——做出结果再答出问题，才算真懂。
DEEP_02 · 性能优化报告 PROFILER CASE
一份带前后对比的优化报告
选一个卡顿场景：Profiler 定位 → DrawCall/GC/物理逐项治理 → 数字收尾（如 24fps→55fps）。这份报告在面试里的价值等于半个 offer。
DEEP_03 · 手写 UI 框架 UI FRAMEWORK
层级管理 + 栈式界面 + 异步加载
十个界面以上的项目没有 UI 框架必乱。自己写一遍，再看 Giraffe/OpenSource 的实现，差距在哪一目了然。
DEEP_04 · 联机 Demo MULTIPLAYER
两人能实际对战的极简联机
自定协议、处理粘包、断线重连、房间管理——做完这一个，网络同步的面试题全部有了具象。
DEEP_05 · 复刻研究 CLONE & LEARN
拆一款爆款的核心循环并复刻
选一款玩法清晰的爆款（吸血鬼幸存者类最合适），复刻其核心 10% 玩法，写一篇"为什么这个循环让人停不下来"的技术+设计复盘——程序策划双视角，面试通吃。
■ 亲历踩坑实录 · 客户端篇
2 WAR STORIES
以下全部来自我们真实项目 · 教程里不会写 · 只有进项目才碰得到
WAR STORY_01 · 热更 HOTUPDATE SPLIT
改一行业务代码，玩家要重下 6.55MB？热更分包的教训
热更 DLL 最初混打在一个包里，改一行业务代码玩家就要全量重下。后来把 DLL 按"业务 / AOT / 第三方"拆成三个子目录，改一行业务代码的重下体积从 6.55MB 降到约 0.6MB。资源分包规则（共享资产重复打包）也是同类问题——教程只教"怎么打热更包"，不教"怎么打得让玩家少下载"。
YooAsset / HybridCLR 实战 分包是体验问题，不只是技术问题
WAR STORY_02 · 运行时 DOMAIN RELOAD TRAP
Play 模式中途改脚本，教程协程直接"暴毙"
Unity 在 Play 模式下改代码触发域重载（Domain Reload），静态状态全部重置、协程被杀——我们的新手引导协程就是这样变成"半死态"的：弹窗残留但引导流程已死。结论进项目才懂：验证流程必须"退出 Play → 等编译完 → 重进"，以及业务代码要能扛住"任意时刻被重置"。
Domain Reload 会杀协程 引擎机制坑 · 文档里有但你不信
