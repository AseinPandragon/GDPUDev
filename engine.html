STEP_01 · C++ 硬功夫（一切的前提） MODERN C++
C++ 要学到"内存模型"这一层
工具 / 引擎岗的 C++ 门槛远高于客户端的"会用"：智能指针与所有权、移动语义、多线程与数据竞争、缓存友好的数据布局。《C++ Primer》当字典查，《Effective C++》精读，语法细节随时查 cppreference。校招笔试的算法题照刷不误（和客户端同一套）。
cppreference.com（C++ 标准库手册） LeetCode 力扣 智能指针 / 移动语义 / 多线程
STEP_02 · 图形学与引擎原理 GAMES 101 / 202 / 104
图形学是必修不是选修，GAMES 104 是世界观
工具岗虽然不直接写渲染，但看不懂渲染管线就没法给美术做提效工具。GAMES 101 打底、202 进实时渲染、104 建立引擎全局观（各系统怎么拼装、资产管线怎么流转）——104 对工具岗的价值甚至比对客户端更大。
GAMES101 · B站 GAMES101 官网 GAMES104 官网（B站可看） Real-Time Rendering 官网
STEP_03 · 编辑器扩展实战（核心作品来源） EDITOR TOOLING
给自己的项目写工具——这就是最好的作品集素材
  • Unity 方向：EditorGUILayout / AssetPostprocessor / 自定义 Inspector，从"批量资源重命名"做到"Excel 表格一键导入 ScriptableObject"，官方手册的 Extending the Editor 章节是主线。
  • UE 方向：Editor Utility / Blueprint 工具 + Python 脚本批处理资产。
  • 进阶：给工具加上进度条、错误报告、可回滚——工程化细节就是"业余工具"和"专业工具"的分界线。
Unity 官方 · 扩展编辑器手册 UE 官方文档 批量处理 / 表格导入 / 一键检查
STEP_04 · 入行路径与作品集 CLIENT FIRST, THEN TRANSFER
应届怎么进工具 / 引擎岗
  • 主路径：应届投客户端 / TA 岗 → 入职后主动接工具需求 → 内部转岗。入职时的"额外技能"（会写编辑器扩展）就是转岗筹码。
  • 作品集：2~3 个编辑器工具（GitHub + 演示 GIF）+ 1 个性能优化案例（Profiler 前后对比截图）。
  • 面试侧重点：C++ 八股 + 图形学基础 + "你为什么想造轮子"——工具岗面试官最怕招到只想写渲染不想做服务的人。
GitHub 演示 GIF > 长篇文档 应届直招少 · 先客户端再转
💡 一句话总结引擎 / 工具方向 引擎工具 = C++ 硬功 × 图形学（101/202/104）× 工程化工具实战。应届走"客户端 → 内部转岗"主路径，编辑器扩展作品就是你的转岗筹码。
■ AI 在这个岗位怎么用（2026 现状）
MUST HAVE
现在所有岗位几乎必用 AI · 但"会用 AI"的前提是"不用也会"
AI WORKFLOW AI-POWERED · HUMAN-VERIFIED
AI 能写脚手架，验证能力才是你的
  • 日常：C++ 代码 review、编译错误与崩溃堆栈解释、工具脚手架生成——AI 对这类"模式化"工作很在行；
  • 红线：引擎底层与性能问题 AI 经常一本正经地错（幻觉重灾区），每个结论都必须能在文档或 Profiler 里验证；
  • 定位：工具岗的价值在"知道该做什么工具"，AI 只加速"怎么做"——需求判断这一半 AI 替代不了。
