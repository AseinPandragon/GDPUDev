■ 这个细分到底在拼什么
WHAT IT TAKES
先看清门槛 · 再决定要不要投入
  • 资源导入导出全流程：从 Maya/PS 到引擎可用资产的每一步；
  • 打包机制原理：AssetBundle / Addressables 的依赖、加载、去重；
  • 版本与热更管理：版本比对、差量包、回滚；
  • 指标意识：包体、首包、加载时间的预算与监控。

■ 这个岗位的一天 · 实际工作内容
A DAY IN LIFE
入职前先知道每天到底在干什么
  • 上午：看打包失败单——资源引用丢失、重名冲突、平台差异；
  • 主力时间：改管线 / 定规则——打包规则、加载策略、监控脚本；
  • 验证指标——包体与加载时间是否达标，超标找原因；
  • 产出物：打包流水线 + 资源规范 + 监控面板。

■ 大学四年怎么走
4-YEAR PLAN
按 2024 级培养方案的课程节奏编排 · 以教务最新通知为准
1
大一 · 底层意识（文件与网络就是全部）
把"一个文件从磁盘到屏幕"的全过程讲清楚
做什么：课内操作系统（文件 IO、进程）与计算机网络（HTTP、CDN、缓存）认真学；课外做一个小练习：用任意语言写一个"本地文件版本管理器"——记录文件改动、能回滚到任意版本，不用 Git，手写。
验收标准：能讲清"HTTP 下载一个文件到本地，中间每一步发生了什么、哪里可能失败"。
避坑：管线的本质是"文件 + 网络 + 版本"三件事，大一就把这三件事的地基打掉。
2
大二 · 手动打包（先把依赖图亲手画出来）
用原生 AssetBundle 手动打包一次：依赖、冗余、加载顺序全踩一遍
做什么：不看任何封装框架，用 Unity 原生 AssetBundle 机制（官方手册）手动完成一次完整打包：标记资源 → 构建包 → 分析依赖 → 运行时加载。把"哪个资源被重复打进几个包"的依赖关系图亲手画出来。
验收标准：能指着依赖图说出"冗余是怎么产生的、三种消除手段各自的代价"。
避坑：直接上封装框架 = 永远不知道框架替你做了什么，出了问题就是黑盒。
3
大三 · 热更方案（生产级工具 + 自建对照）
用 YooAsset 做一套完整热更方案：版本比对、增量下载、失败回滚，全流程可演示
做什么：主方案用 YooAsset（GitHub） + 官方文档：搭建远端资源服 → 打包 → 版本比对 → 增量下载 → 校验 → 回滚，全流程做一个可现场演示的 demo；对照组用 Addressables（官方手册）做同样的最小流程，写一篇对比笔记。
验收标准：现场演示"改一个数值 → 不重装包 → 游戏内生效"，且能回答"下载中断了怎么办"。
避坑：只会调框架 API 不算懂管线——追问"框架替你做了什么"必须有答案。
4
大四 · 方案定稿（从需求到决策链）
作品集 = 热更 demo + 一篇《方案选型与决策链》文档，指标全部量化
做什么：整理一份选型文档：需求假设（包体/首包/加载时间目标）→ 候选方案对比 → 最终决策与理由 → 踩坑记录。指标全部量化：首包压到多少、加载时间从多少到多少。
验收标准：文档能给一个没做过管线的同学看，他照着能搭出同样的流程。
避坑：面试讲方案最忌"我用了 XX 因为它好用"——要讲清楚"备选有哪些、各自的代价、为什么选它"。
■ 作品集长什么样 · 常见误区
PORTFOLIO & TRAPS
作品集定生死 · 别在错误方向上努力
  • 标配：热更 demo + 管线流程图 + 指标数据；
  • 误区：只会点打包按钮没理解依赖图——一键工具的便利不是你的能力；
  • 加分：踩过"线上资源丢失"级别的坑并写出复盘。
