■ 这个细分到底在拼什么
WHAT IT TAKES
先看清门槛 · 再决定要不要投入
  • Python：Maya / Blender 插件的主力语言，字符串与文件批处理要顺手；
  • DCC 软件脚本接口：Maya cmds/mel、Blender bpy，会查官方文档比背 API 重要；
  • 规范思维：资产命名、目录结构、导入规则——规范是管线的基础设施；
  • 一点 UI：PySide 让工具能交付给非技术同事用。

工具 / 课程作用 / 对应环节
Python 入门（廖雪峰教程，免费）语法入门到实战的主教材，学完立刻转向"解决自己的重复劳动"；
Python + PySide（官方文档）写 Maya/Blender 插件与工具界面的事实标准；

课内：数据库原理批量数据处理的思维底子。
■ 这个岗位的一天 · 实际工作内容
A DAY IN LIFE
入职前先知道每天到底在干什么
  • 上午：收需求——美术说"贴图要批量改名"，你要追问出真实痛点是什么；
  • 主力时间：写工具 / 改插件——从脚本到带界面的小工具，写完自己先当用户测一遍；
  • 答疑与迭代——工具发布后处理使用问题，收集下一个需求；
  • 产出物：DCC 插件、批处理脚本、资产规范文档。

■ 大学四年怎么走
4-YEAR PLAN
按 2024 级培养方案的课程节奏编排 · 以教务最新通知为准
1
大一 · 脚本起步（从自己的麻烦开始）
跟完廖雪峰 Python 教程，写出 10 个解决自己重复劳动的小脚本
做什么：主教材用廖雪峰 Python 教程（免费、中文、可在线运行），学完基础语法立刻转向"用起来"：批量重命名照片、整理下载文件夹、合并几十个表格——一年攒 10 个真实用过的脚本。
验收标准：10 个脚本里至少 3 个是你现在还会反复用的。
避坑：别从"背语法"开始，从"解决自己的麻烦"开始——工具 TA 的全部价值就长在这个习惯上。
2
大二 · 第一个插件（学会听需求）
做第一个 Maya/Blender 插件：先做无 UI 脚本，跑通再包界面
做什么：文档为主——Maya 官方 Python 命令文档（help.autodesk.com/MAYAUL）或 Blender Python API（docs.blender.org/api），找一个真实用户（同学/社团里的画手）提需求，做出第一个"别人真的在用"的插件。
验收标准：插件被你自己以外的至少 1 个人用过，且你根据他的反馈改过一版。
避坑：别先写 UI——没有核心功能的界面是玩具；先让脚本在命令行跑通，再包一层界面。
3
大三 · 真实服役（工具是养出来的）
完整工具（含 UI）+ 规范文档，在比赛队/工作室真实服役并迭代
做什么：给比赛队或工作室做一件"每天都在被用"的工具（批量检查、命名校验、导入导出器），界面用 PySide（官方文档：doc.qt.io/qtforpython），配一份使用文档和更新记录。
验收标准：工具被 3 人以上使用过，且你能拿出"v1 被吐槽 → v2 改进"的迭代记录——这段过程比成品更打动面试官。
避坑：没人用的工具不算作品，算作业；需求来源一定要是真实用户的真实痛点。
4
大四 · 讲价值（用数据说话）
作品集量化收益：每个工具能回答"给谁用、省了多少时间、覆盖多少资产"
做什么：把每个工具整理成"问题 → 方案 → 使用数据"三段式：原来 2 小时的手工流程现在 5 分钟、覆盖了多少资产、迭代了几版。演示录成 gif/视频，附核心代码段。
验收标准：面试官问"这个东西真有人用吗"，你能当场展示使用记录或用户原话。
避坑：只放功能截图不放使用数据的工具集，在面试官眼里和课程作业没区别。
■ 作品集长什么样 · 常见误区
PORTFOLIO & TRAPS
作品集定生死 · 别在错误方向上努力
  • 标配：工具演示 gif/视频 + 使用说明 + 一段核心代码；
  • 量化是灵魂：把 2 小时手工流程压到 5 分钟，比十个炫技功能有说服力；
  • 规范文档也算作品：能看到你的系统性思维；
  • 误区：只炫技不解决真实痛点——没人用的工具等于没做。
