💡 一句话定位 数媒技在策划岗里优势最大的方向，没有之一：既是"最懂程序的策划"，又是"最懂设计的半个程序"——能自己进引擎把设计做成可玩原型，这种人在项目里极其稀缺，缺口明显。
■ 这个细分到底在拼什么
WHAT IT TAKES
先看清门槛 · 再决定要不要投入
  • 引擎熟练度：Unity/UE 编辑器 + 可视化脚本（蓝图）是日常工具，不是加分项；
  • 轻量代码能力：C# 到"能写工具、能改逻辑"的程度即可，不要求向客户端看齐；
  • 设计翻译力：把策划案翻译成程序能懂的技术方案，把技术限制翻译回设计取舍；
  • 工具意识：给团队做小工具（关卡检查器、配置校验）是最容易被看见的产出。
■ 工具链 与 课内对应课程
TOOLS & COURSES
工具是手段不是目的 · 招聘看的是"用工具做出的东西"

■ 这个岗位的一天 · 实际工作内容
A DAY IN LIFE
入职前先知道每天到底在干什么
  • 上午：实现支持——把策划侧的系统需求直接在引擎里搭出来：关卡逻辑、UI 流程、配表结构；
  • 主力时间：写策划侧脚本——Lua / Python / 可视化脚本，做"不等程序排期也能改"的玩法逻辑；
  • 做小工具——给策划同事做配表校验、关卡检查器之类的小工具，是团队效率放大器；
  • 和程序划边界——什么逻辑进代码、什么逻辑留配置和脚本，边界感是这个岗位的核心素养；
  • 产出物：可运行的玩法原型、策划工具、脚本逻辑库。
■ 面试与校招 · 会考什么
INTERVIEW MAP
TP 面试就是"策划岗里最像程序面试"的 · 直接考手
考察环节常见形式与真题方向
实操题现场用引擎 + 脚本实现一个小玩法（可拾取道具 + 计分 + 存档），直接考动手能力；
配表设计给一个玩法需求，现场设计配置表结构——考"数据驱动"而不是"写死在代码里"的思维；
沟通题"程序说实现不了怎么办"——考双向翻译能力和折中方案设计，不是考谁嗓门大；
作品集深挖demo 里哪部分是你写的、为什么这么架构，会一层层问到底——别放不是自己做的部分；
加分项会用 Profiler 看瓶颈、懂一点性能优化——策划岗里独一份的差异化。
■ 大学四年怎么走
4-YEAR PLAN
按 2024 级培养方案的课程节奏编排 · 以教务最新通知为准
1
大一~大二 · 双线启动 DUAL TRACK
代码课认真学 + 引擎早接触
程序设计基础别水（这是 TP 的代码地基），同时大二课内《三维游戏开发技术》把引擎玩熟。
2
大二暑假 · 第一次落地 FIRST BUILD
把自己的一个设计做成可玩原型
不用大：一个完整的小机制（如钩锁移动+敌人交互）从设计文档到可玩全部自己来。
3
大三 · 工具 + 原型成套 TOOLS & PROTOTYPE
给团队做小工具 + 一章可玩内容
做一个解决真实痛点的小工具（表格校验/批量命名/关卡检查器），再加一个可玩的关卡或玩法原型。
4
大四 · 三件套 PORTFOLIO
可玩 demo + 设计文档 + 实现说明
面试 TP 的标准三件套：能玩的东西、为什么这么设计、为什么这么实现。
■ 作品集长什么样 · 常见误区
PORTFOLIO & TRAPS
作品集定生死 · 别在错误方向上努力
  • 标准三件套：可玩 demo（在线可玩最好）+ 设计文档 + 实现说明——三者缺一就只是"会用引擎的策划"或"想转策划的程序"；
  • 小工具最容易被看见：解决真实痛点的工具比炫技 demo 更打动面试官；
  • 常见误区：不懂程序边界瞎承诺；或代码太重，把自己当成半个客户端；
  • 薪资提示：TP 属于策划里偏高的一档，且数媒技背景在 JD 里是明确加分项（见 jobs 页）。
