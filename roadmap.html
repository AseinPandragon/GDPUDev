■ SEC.02 · 深挖方向 01：技术美术 TA
4 STEPS
先打地基 → 再进引擎 → 跟人学 → 作品集 · 顺序比速度重要
STEP_01 · 地基（大二前打完最划算） GAMES 101 → 202 → 104
图形学三件套：GAMES 101 / 202 / 104
国内图形学入门公认的起点，B站就能看，不用管它是哪年录的——图形学基础的衰减期比框架长得多。
  • GAMES 101 现代计算机图形学入门：变换、光栅化、着色、光线追踪。作业认真写，光看不行。它决定你能不能看懂 Shader 背后的数学。
  • GAMES 202 高质量实时渲染：阴影、全局光、实时降噪——直接对应游戏渲染岗的日常话题。
  • GAMES 104 现代游戏引擎：建立"引擎全局观"，知道一个引擎由哪些系统拼起来。作业量力而行，但一定要看完，它会改变你看 Unity/UE 的方式。
GAMES101 · B站 GAMES101 官网 GAMES202 官网（B站搜 GAMES202） GAMES104 官网（B站可看） Real-Time Rendering 官网
《Real-Time Rendering》别通读，当字典查 碰到"这效果什么原理"再翻对应章节
STEP_02 · 引擎双线（与 STEP_01 并行） UNITY: WRITE / UE: BREAK
Unity 里动手写，UE 里开眼界拆
两条线不是二选一，是分工不同：
  • Unity 线（动手）：ShaderLab / HLSL 从最简单的 Unlit 开始写起，逐个实现卡通着色、描边、溶解、billboard、屏幕后处理。每个效果录一段视频存进作品集文件夹。
  • UE 线（拆解）：去看官方工程示例（如 Lyra、City Sample），拆解官方插件——重点不是学 UE API，而是看"一个工业级项目怎么组织材质库、后处理栈、资产管线"。见过好结构，才知道自己写的有多野。
UE 官方 Lyra 示例文档 UE 官方学习社区 Unity 官方文档 知乎 · 图文深度分析主阵地 TA / 渲染专栏 → 建自己的知识库
STEP_03 · 跟人学（穿插全程） FOLLOW THE ACTIVE ONES
关注这些 UP 主 / 作者：kerry、月神、三彩
自学最容易死在"不知道自己不知道什么"上。跟着活跃的 TA 向作者走，他们的更新内容就是行业里当下在关心的问题，比自己闷头翻教程高效。遇到系列教程就跟着把 Demo 做一遍，光收藏不算学。
B站：kerry 月神 三彩 B站 + 知乎双平台跟更
STEP_04 · 作品集（大三上必须启动） PORTFOLIO > GPA
TA 的作品集长什么样
  • 3~5 个有讲解的渲染效果 Demo：每个附"效果视频 + 实现思路 + 对比截图（开启/关闭）"，最好附 GitHub 仓库。
  • 1 个工具型作品：编辑器扩展或美术提效小工具，展示你不只会写特效。
  • 1 个"进过真机"的项目：哪怕是小项目，只要在真机上跑过、优化过，含金量就超过十个只在编辑器里好看的 Demo。

■ SEC.03 · 深挖方向 02：客户端程序（Unity C# / UE C++）
4 STEPS
数媒技走的人最多的路 · 从"会拖组件"到"能独立交付完整游戏"
STEP_01 · 语言基础（一切的地基） C# FIRST
先把 C# 学扎实：唐老狮 C# 四部曲
直接跳过语言去拖引擎组件，是数媒技学生最常见的翻坑方式。推荐的免费系统课是唐老狮（B站：一唐老狮一）的 C# 四部曲：入门 → 核心 → 进阶 → 数据结构与算法，讲得细、有作业、节奏适合自学，B站整套免费看。四部曲全部过完，你才有资格谈"会用 Unity 写逻辑"。
唐老狮 · B站个人空间 C#入门 → C#核心 → C#进阶 → 数据结构与算法 免费 · 有课后作业
STEP_02 · 引擎实操（与 STEP_01 后半并行） MAKE IT PLAYABLE
Unity 入门：跟着做，别只看
唐老狮的 Unity 系列覆盖 MonoBehaviour 生命周期、UI（UGUI）、物理、动画、寻航等全部常用模块，跟着把每个模块的小案例做出来；同时配合 Unity 官方文档查 API——教程负责入门，文档负责精确。目标：能不抄教程独立做出贪吃蛇 / 打飞机 / 平台跳跃级别的小游戏。
唐老狮 · Unity 系列教程 Unity Learn 官方教程 Unity 官方文档
STEP_03 · 内功（大二下~大三上） DATA STRUCTURE + FRAMEWORK
数据结构、设计模式与"框架感"
校招笔试躲不开数据结构与算法（LeetCode 简单~中等量级即可），而面试更看你在项目里怎么组织代码：对象池、状态机、事件系统、单例、MVC 分层——这些"框架感"是从写 Demo 到写项目的分水岭。建议每个小机制都自己封装一遍，再回头看别人的实现对比。
LeetCode 力扣 对象池 / 状态机 / 事件系统 / UI框架
STEP_04 · 作品集（大三上必须启动） SHIP IT
客户端的作品集长什么样
  • 1~2 个完整可玩的游戏：能安装、有音效、有结算、能重开，最好打过真机包（安卓 APK 能给别人装上玩）。
  • GitHub 仓库：README 写清楚玩法、架构图和技术亮点（对象池怎么省内存、UI 框架怎么分层）。
  • UE C++ 支线（加分项）：想走 UE 方向的，C++ 四部曲（唐老狮也有 UE 系列的 C++ 基础）→ UE 官方文档 → C++ 写小游戏逻辑，应届 UE 岗少但竞争更小。
唐老狮 · UE C++ 四部曲 UE 官方文档 GitHub
💡 一句话总结客户端方向 客户端 = 语言底子（C# 四部曲 / C++）× 引擎系统知识（UI/物理/动画/热更）× 完整项目（打包到真机、别人真的玩过）。面试官问"你这个项目的内存峰值多少、包体多大"，答不上来就是 Demo 选手。
■ SEC.04 · 深挖速写：策划 / 引擎工具 / 美术 / 其他出口
4 TRACKS
每个方向给"最小可行路线" · 深度版随需求再扩
TRACK_A · 游戏策划（含技术策划 TP） DESIGN / TP
策划的最小可行路线
  • 读书打底：《游戏设计艺术》《体验引擎》两本足够入门，读的时候对着自己玩过的游戏做验证。
  • 拆解报告：每周拆一个系统或关卡（战斗节奏 / 抽卡数值 / 新手引导），写 2000 字以上——这就是策划的核心作品集。
  • 动手能力：Unity 里能摆关卡、写简单脚本；Excel 数值表必须熟练（VLOOKUP、模拟器）。
  • TP 加分项：Unity C# 或 UE 蓝图能跑通，就能做技术策划，缺口比纯案头大。
indienova 独立游戏社区 机核 GCORES 作品 = 拆解报告 + 可玩原型 + 数值表
TRACK_B · 引擎 / 工具开发 ENGINE / TOOL
引擎工具的最小可行路线
  • 前提：先走客户端 1~2 年的逻辑仍然成立——工具岗要理解使用者的痛点，应届直招极少。
  • C++ 硬功夫：内存模型、智能指针、多线程；图形学 GAMES 101/202 是必修不是选修。
  • 练手项目：给自己的 Unity 项目写编辑器扩展（批量资源处理 / 数据表格导入工具），这就是最好的作品。
编辑器扩展 = 入门作品 建议客户端转岗进入
TRACK_C · 美术（原画/3D/动作/特效） ART / VFX
美术的最小可行路线
  • 先选细分再投入：原画拼造型与设计；3D 场景/角色拼软件链（Blender/Maya → Substance → 引擎）；动作拼动态审美；特效拼"技术+审美"复合——对数媒技最友好的是特效 VFX。
  • 基本功不能省：速写、结构、色彩，每周固定练习量，课内强度不够就自己补。
  • 作品集：ArtStation / 米画师，宁缺毋滥，10 张精品 > 50 张练习。
  • 特效岗：Unity 粒子系统 / UE Niagara + Houdini 入门，作品直接在引擎里录屏。
ArtStation VFX 与 TA 路线互通
TRACK_D · 服务端 / QA / 发行 SERVER / QA / PUB
其他出口的最小可行路线
  • 服务端：Go 或 Java 或 C++ 选一门 → 网络（TCP/HTTP）→ 数据库（MySQL/Redis）→ 写一个多人 Demo（帧同步或状态同步）。和数媒技课程重合度低，适合纯技术流。
  • QA 测试：入门靠细心与用例思维，天花板靠自动化（Python + 引擎测试框架），能写自动化脚本的测试很值钱。
  • 发行运营：偏数据与商务，技术背景在"懂游戏能和研发对话"上是优势，但不算研发岗，慎重选择。
服务端作品 = 联机 Demo QA 别只会点点点
■ SEC.05 · 亲历踩坑实录（为什么"课本外"的东西更重要）
6 WAR STORIES
以下全部来自我们真实项目 · 教程里不会写 · 只有进项目才碰得到
WAR STORY_01 · 渲染排序 URP CAMERA STACK
UI 弹窗怎么调 Layer 都不生效？因为 URP 里 Layer 根本不管排序
技能弹窗死活显示不出来/层级错误，查了半天 Layer 剔除——真相是：URP 的 Overlay 相机栈里，Layer 只管相机剔除，实际显示顺序由相机列表顺序和 Sorting Layer 决定。最后靠把弹窗挂到最上层 Canvas + 指定 Sorting Layer 才解决。
GAMES101 教原理 "引擎具体怎么排"只能靠项目毒打
WAR STORY_02 · 深度与遮挡 Z-TEST TRAP
世界空间图标被场景模型"吃"掉一半：ZTest 的教训
给技能做箭头指示图标，按物体包围盒定位后仍然被挡——精灵枢轴和半深度都没算进去。世界空间 UI/图标必须在锚点定位之外额外考虑与相机的深度关系（沿相机方向再推一段），否则 ZTest 会替你做"正确的"遮挡，挡掉你想显示的东西。
ZTest 是"对的"，但不是你要的
WAR STORY_03 · 资源与打包 SHADER STRIPPING
编辑器里好好的，真机上材质全变粉色（或直接报空）
运行时用 Shader.Find 动态建材质，编辑器一切正常，真机上直接 ArgumentNullException 中断加载——因为没被资源引用的 shader 打包时会被裁剪，真机上 Find 返回 null。正确做法是多候选查找 + 内置材质兜底 + 全失败就跳过赋值。
打包管线知识 不进项目永远碰不到
WAR STORY_04 · 粒子特效 VFX LOOP TRAP
循环特效越叠越亮：burst 粒子的 duration 陷阱
把循环特效 main.loop 打开后，画面上的粒子一轮比一轮多——原因是 ParticleSystem 的 duration 没有覆盖到最长粒子寿命，burst 每个周期都在叠。调 VFX 不是拖拖参数，每一条曲线和时长都要能解释。
loop=true 时 duration ≥ 最长寿命
WAR STORY_05 · 客户端 / 热更 HOTUPDATE SPLIT
改一行业务代码，玩家要重下 6.55MB？热更分包的教训
热更 DLL 最初混打在一个包里，改一行业务代码玩家就要全量重下。后来把 DLL 按"业务 / AOT / 第三方"拆成三个子目录，改一行业务代码的重下体积从 6.55MB 降到约 0.6MB。资源分包规则（共享资产重复打包）也是同类问题——教程只教"怎么打热更包"，不教"怎么打得让玩家少下载"。
YooAsset / HybridCLR 实战 分包是体验问题，不只是技术问题
WAR STORY_06 · 客户端 / 运行时 DOMAIN RELOAD TRAP
Play 模式中途改脚本，教程协程直接"暴毙"
Unity 在 Play 模式下改代码触发域重载（Domain Reload），静态状态全部重置、协程被杀——我们的新手引导协程就是这样变成"半死态"的：弹窗残留但引导流程已死。结论进项目才懂：验证流程必须"退出 Play → 等编译完 → 重进"，以及业务代码要能扛住"任意时刻被重置"。
Domain Reload 会杀协程 引擎机制坑 · 文档里有但你不信
【待补充 · 学长亲历口述区】　你自己的入坑契机、第一次写出能看的 Shader 是什么时候、被哪门课劝退/点醒——这些只有你能写。说一段，我们就填进来。
■ SEC.06 · 不分方向都成立的几条
6 RULES
行业共识里最经得起时间的部分
RULE_01 PORTFOLIO FIRST
作品集 > 绩点（但别挂科）
游戏公司校招看的是"你做过什么"：能跑的 Demo、双击就能玩的成品、GitHub 仓库。绩点保底不挂科即可，时间要大量投给项目。
RULE_02 GAME JAM ASAP
参加 Game Jam，越早越好
48 小时内做一款完整游戏，是最快暴露"你以为会、其实不会"的方法。CiGA 主办的线下 Game Jam 每年暑期报名，Global Game Jam 中国区每年初开赛，大一暑假就可以开始参加。
CiGA Game Jam 报名页
RULE_03 FINISH THINGS
做完整的项目，别囤半成品
十个 30% 完成度的项目不如一个 100% 的。完整意味着：能安装、有音效、有结算、能重开。我们做完整项目时学到的东西（打包、热更、真机适配）没有一样出现在教程里。
RULE_04 ENGLISH = INFRA
英语不是加分项，是基础设施
官方文档、引擎 release note、图形学论文、报错搜索——一手信息全是英文。靠翻译软件可以活，但速度差一截，日积月累就是差距。
RULE_05 AI AS LEVER
把 AI 当杠杆，别当拐杖
AI 能帮你解释报错、生成模板、查 API 用法，效率翻倍；但基础概念跳过 AI 直接要答案，你就失去了建立自己理解的机会。判断标准：让 AI 写的东西，你能逐行给别人讲明白吗？
RULE_06 · 时间线 REAL TIMELINE
实习时间线（现实版）
大二暑假前：作品集启动 + 第一个完整项目。大三上：秋招提前批开始投（别以为秋招是"秋天"，七月就开始了）。大三暑假：日常实习。等大四再准备就晚了，这条线每年都在提前。

NO SUGARCOATING
不贩卖焦虑 · 也不画饼
  • 行业有周期。招聘量随版号、市场波动明显，你入学时的行情和毕业时可能完全不同。所以选方向优先选"底层能力可迁移"的（图形学、C++、工程能力），而不是押注某个风口引擎。
  • 大厂 / 中小厂 / 外包体验完全不同。大厂分工细、螺丝钉但体系化；小厂什么都干、成长快但野蛮；外包是不少人的第一跳板，不丢人，但要清楚它是一跳不是终点。
  • 薪资不写在指南里。网上流传的数字水分大且随年份剧烈变化，建议直接去面几轮、或找在职学长要当届 offer 实况，比任何攻略都准。
  • 数媒技不是"劣势专业"。游戏行业里技术+审美复合背景的人本来就该走复合岗位（TA、TP、特效），对口的赛道你不走，非要跟科班 CS 拼 pure 程序岗才是把自己放错位置。
